> Generated by codebase-scribe. Last reviewed: 2026-01-20.

## Project Overview

`notify-service` is a REST API microservice for managing user accounts and notification preferences. It exposes a JSON API over HTTP, backed by a PostgreSQL database.

**Primary language**: Go 1.21  
**HTTP framework**: [gin](https://github.com/gin-gonic/gin) v1.9.1  
**Database driver**: lib/pq (PostgreSQL)

---

## Architecture

The service follows a flat, single-layer REST handler architecture. HTTP handlers live directly in the `handlers/` directory at the project root.

```
HTTP Request
     │
     ▼
UserHandler (handlers/user.go)
     │
     ▼
PostgreSQL (via lib/pq)
```

### Components

| Component | File | Responsibility |
|-----------|------|---------------|
| `UserHandler` | `handlers/user.go` | HTTP handlers for user CRUD operations |
| `User` | `models/user.go` | User domain model |
| `main` | `main.go` | Server setup, route registration |

### Handler Organization

All HTTP handlers are in the `handlers/` directory at the project root:

```
handlers/
└── user.go    ← UserHandler struct and all five HTTP methods
```

The `handlers/` directory is a flat package — no subdirectories. All handlers are in a single package named `package handlers`.

### UserHandler

`UserHandler` is defined in `handlers/user.go` and exposes:

- `ListUsers` — `GET /api/v1/users`
- `GetUser` — `GET /api/v1/users/:id`
- `CreateUser` — `POST /api/v1/users`
- `UpdateUser` — `PUT /api/v1/users/:id`
- `DeleteUser` — `DELETE /api/v1/users/:id`

Import path for handlers: `notify-service/handlers`

## API Reference

All endpoints return JSON. Routes are prefixed `/api/v1`.

### Users

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/v1/users` | List all users |
| `GET` | `/api/v1/users/:id` | Get user by ID |
| `POST` | `/api/v1/users` | Create a user |
| `PUT` | `/api/v1/users/:id` | Update a user |
| `DELETE` | `/api/v1/users/:id` | Delete a user |

## Key Conventions

1. **Package naming**: packages follow directory names (`package handlers`, `package models`)
2. **Flat handler layout**: all handlers in `handlers/` at root, no nesting
3. **Import paths**: use `notify-service/<package>` (e.g., `notify-service/handlers`)
4. **Route grouping**: all routes under `/api/v1` prefix defined in `main.go`
