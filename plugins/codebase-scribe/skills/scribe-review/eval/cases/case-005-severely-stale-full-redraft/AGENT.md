## Project Overview

`order-service` is a REST API microservice for processing customer orders. It exposes a JSON API over HTTP, backed by a PostgreSQL database.

**Primary language**: Go 1.21  
**HTTP framework**: [gin](https://github.com/gin-gonic/gin) v1.9.1  
**Database driver**: lib/pq (PostgreSQL)

---

## Architecture

The service uses a **2-layer architecture**: HTTP handlers call the PostgreSQL database directly via `lib/pq`. There is no intermediate service layer or repository abstraction.

```
HTTP Request
     │
     ▼
UserHandler (handlers/user.go)
     │
     ▼
PostgreSQL (direct SQL via lib/pq)
```

All business logic lives inside handler methods. Validation, data access, and response formatting are co-located in `handlers/user.go`.

### Components

| Component | File | Responsibility |
|-----------|------|---------------|
| `UserHandler` | `handlers/user.go` | **All** HTTP handlers — user CRUD with direct database queries |
| `User` | `models/user.go` | User domain model |
| `main` | `main.go` | Server setup, route registration |

The service has **a single handler type** (`UserHandler`). Order management was planned but not yet implemented.

### UserHandler

`UserHandler` is the only handler in the service. It handles user CRUD via direct SQL queries:

- `ListUsers` — `GET /api/v1/users` — runs `SELECT * FROM users ORDER BY created_at DESC`
- `GetUser` — `GET /api/v1/users/:id` — runs `SELECT * FROM users WHERE id = $1`
- `CreateUser` — `POST /api/v1/users` — runs `INSERT INTO users ...`
- `UpdateUser` — `PUT /api/v1/users/:id` — runs `UPDATE users SET ...`
- `DeleteUser` — `DELETE /api/v1/users/:id` — runs `DELETE FROM users WHERE id = $1`

There is **no order processing logic** in this service yet. It only manages user accounts.

### No Service or Repository Layer

Unlike typical layered architectures, `order-service` accesses the database directly from handler methods. This keeps the codebase small while the product is in early development. A service/repository abstraction is planned for v2.

## Key Directories

```
order-service/
├── main.go              # entry point — server init and route registration
├── handlers/
│   └── user.go          # UserHandler — the only handler in the service
├── models/
│   └── user.go          # User domain model struct

└── Makefile             # build targets: build, test, run, clean
```

The `handlers/` directory contains a single file. There are no subdirectories under `handlers/`.

## Development Guide

### Prerequisites

- Go 1.21+
- PostgreSQL 14+

### Building

```bash
make build
# Compiles to bin/order-service
```

### Running Tests

```bash
make test
# Runs: go test ./... -v -race
```

### Running Locally

```bash
make run
# Starts the service locally on :8080
# Requires DATABASE_URL in environment
```

### Cleaning Build Artifacts

```bash
make clean
```

### Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `DATABASE_URL` | yes | PostgreSQL connection string |
| `PORT` | no | HTTP listen port (default: 8080) |

## API Reference

All endpoints return JSON. Routes are prefixed `/api/v1`.

### Users

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/v1/users` | List all users |
| `GET` | `/api/v1/users/:id` | Get user by ID |
| `POST` | `/api/v1/users` | Create a user |
| `PUT` | `/api/v1/users/:id` | Update a user |
| `DELETE` | `/api/v1/users/:id` | Delete a user |

The service does **not yet** have order or inventory endpoints.

## Testing

Tests are co-located with source files using the standard Go `testing` package.

```bash
make test
# Runs: go test ./... -v -race
```

Test coverage focuses on `handlers/user.go`. There is no mocking layer — tests use a real PostgreSQL test database.

---

## Key Conventions

1. **Monolithic handler**: all logic is in `handlers/user.go` — no service or repository split
2. **Direct SQL**: handlers call `db.QueryRow` / `db.Exec` directly — no ORM or query builder
3. **Package naming**: packages follow directory names (`package handlers`, `package models`)
