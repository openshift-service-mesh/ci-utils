> Generated by codebase-scribe. Verified accurate as of 2026-05-01.

## Project Overview

`user-service` is a REST API microservice that manages user accounts. It exposes a JSON API over HTTP, backed by a PostgreSQL database. The service is stateless and horizontally scalable.

**Primary language**: Go 1.21  
**HTTP framework**: [gin](https://github.com/gin-gonic/gin) v1.9.1  
**Database driver**: lib/pq (PostgreSQL)

---

## Architecture

The service follows a single-layer REST handler architecture. HTTP requests are received by `UserHandler` in `handlers/user.go`, which performs validation and direct database access.

```
HTTP Request
     │
     ▼
UserHandler (handlers/user.go)
     │
     ▼
PostgreSQL (via lib/pq)
```

### Components

| Component | File | Responsibility |
|-----------|------|---------------|
| `UserHandler` | `handlers/user.go` | HTTP handlers for user CRUD operations |
| `User` | `models/user.go` | User domain model |
| `main` | `main.go` | Server setup, route registration, startup |

### UserHandler

`UserHandler` (defined in `handlers/user.go`) exposes five HTTP methods:

- `ListUsers` — `GET /api/v1/users` — returns a paginated list of users
- `GetUser` — `GET /api/v1/users/:id` — returns a single user by ID
- `CreateUser` — `POST /api/v1/users` — creates a new user record
- `UpdateUser` — `PUT /api/v1/users/:id` — updates an existing user
- `DeleteUser` — `DELETE /api/v1/users/:id` — removes a user record

All routes are mounted under the `/api/v1` prefix via a `gin.RouterGroup`.

### User Model

The `User` struct (defined in `models/user.go`) contains:

```go
type User struct {
    ID        string    // UUID primary key
    Email     string    // unique user email
    Name      string    // display name
    CreatedAt time.Time // creation timestamp
    UpdatedAt time.Time // last update timestamp
}
```

## API Reference

All endpoints return JSON. Authentication is handled by an upstream API gateway (not in this service).

### Users

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/v1/users` | List all users (paginated) |
| `GET` | `/api/v1/users/:id` | Get user by ID |
| `POST` | `/api/v1/users` | Create a user |
| `PUT` | `/api/v1/users/:id` | Update a user |
| `DELETE` | `/api/v1/users/:id` | Delete a user |

#### Request: Create User

```json
POST /api/v1/users
{
  "email": "alice@example.com",
  "name": "Alice"
}
```

#### Response: 201 Created

```json
{
  "id": "a1b2c3d4",
  "email": "alice@example.com",
  "name": "Alice",
  "created_at": "2026-05-01T12:00:00Z",
  "updated_at": "2026-05-01T12:00:00Z"
}
```

## Key Conventions

1. **Package naming**: packages follow directory names (`package handlers`, `package models`)
2. **Error responses**: all errors return `{"error": "<message>"}` with the appropriate HTTP status
3. **Route grouping**: all routes are under the `/api/v1` prefix defined in `main.go`
4. **No middleware auth**: authentication is external; this service trusts all incoming requests

## Operational Notes

- The server listens on `:8080` by default (set `PORT` to override)
- Graceful shutdown is not yet implemented — deploy behind a load balancer that drains connections
- The service is stateless; all state is in PostgreSQL
